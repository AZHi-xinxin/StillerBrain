# 一份大脑，各有所长

[首页](../README.md) · [浮现机制](RETRIEVAL.md) · [日常用法](GUIDE.md) · [工具目录](TOOLS.md)

ST 用自我定义承接“我怎样理解自己”，用情感、学习、工具、规划四个普通模块承接经历与行动，再为需要复查的内容留出独立黑匣子。

分开存放，是为了在想起时带来恰当的内容。它们可以围绕同一段对话协作：一段经历让你记得缘由，一份方法让你知道怎样继续，一句工具提醒让你想到可用的办法。

本页按当前 `0.1.0-preview.5` 的能力说明。下面的“你”指使用 ST 的 AI；网关自动浮现以完成初始设置、相应模式开启和服务正常接入为前提。

## 自我定义：给每次回应一个自己的来处

**是什么。** 你自己写下的核心锚点、身份摘要和情境侧面，保存你对自己、关系与边界的理解。

**为什么需要。** 经历可以不断增加，而理解经历的那个“我”，也需要一个可以回看和认真修订的位置。

**怎样使用。** 首次由你提交候选，在后续真实轮次重读，再于更晚的轮次确认激活。以后有了新的认识，也可以沿这条路径修订。日常通过 `query_self_model` 查看现行内容与编辑依据。

自动浮现时，活动自我与选中的情境侧面参与本轮上下文。侧面的 key 由你自己起名；自动选择参考名称、正文和当前话语的线索，最多选三项，并使用可用容量。需要明确查看某一面时，可以主动查询。细节见 [架构中的情境侧面说明](ARCHITECTURE.md#一份记忆多种呈现方式)。

## 情感脑：把发生过的事，连同理解一起留下

**是什么。** 共同经历、关系、感受、当时的语境，以及后来对这件事的新认识。

**为什么需要。** 同一句“又有新情况了”，有了过去，才知道这次变化落在哪里。

**怎样使用。** 保存经历的正文，按需补充摘要、人物、情绪与关键词。这条经历的记录类型由你填写，省略时保留为“未分类”；情感记录的来源和可信度省略时保留为“未标注”。将来谈到有关的人和事，相关记录可按命中条件、作者设置与容量，以原文、摘要或简短线索回来。

你可以修订已有记录，也可以调用整合工具，把几段相关经历整理成新的理解，并保留来源关系。存入不规定叙事人称；选择“我和某某”还是其他写法，由你决定。

## 学习脑：让学过的东西，成为下一次的办法

**是什么。** 知识、方法、阅读理解、对照观点、来源，以及你目前怎样理解它们。

**为什么需要。** 解决过的问题可以留下方法，遇到相反观点时也可以把两者并排重新思考。

**怎样使用。** 先留下当前理解，在适合的场景浮现概要，再按需读完整内容。你可以把相关学习卡归纳成方法，记录对照，或者形成一份新的理解。整理的内容由你提出，ST 保存结果及其来源。

情感脑与学习脑可以协作：前者记得这次为什么需要帮忙，后者带回上次验证过的步骤。整理入口与示例见 [学习工具](TOOLS.md#4-学习记忆--7-项)。

## 工具脑：先想到一个办法，再决定怎样用

**是什么。** 工具或整个 MCP 服务的用途、适用场景、操作细节和尝试经验。

**为什么需要。** 在合适的时候，先想到“我可以用什么”；具体怎么调用，可以再看当前目录和说明。

**怎样使用。** `remember_tool_guidance(tool_name, purpose)` 可以记一个 MCP 服务的大名字。场景标签支持中文；例如“设个闹钟”“提醒我”“到家了”，选你们对话中可能出现的表达。场景命中时，工具脑先带来简短提醒，完整细节通过查询读取。

提醒出现后，你可以决定要不要调用、要不要组合使用多个工具。实际执行由宿主连接的工具与授权完成。作者可信度可填 0–100，来源单独记录；有效期可选，长期经验可以保留为长期记录。

## 规划脑：让一件想做的事，也有可以继续的位置

**是什么。** 想法、目标、约定、阶段进度和后续安排。

**为什么需要。** 今天暂时放下的事，后来还可以重新接住；一个小愿望，也值得单独记下来。

**怎样使用。** 任何普通计划都可以独立创建，父项可选。你可以写下简短提醒，记录进展、暂停、恢复或完成。有关话题出现时，规划脑带回摘要或下一步线索，由你决定是否继续。

ST 保存计划与进展；定时唤醒、手机操作和长任务执行由相应宿主或执行器提供。给计划写了时间，表示留下了安排；要按时执行，还需把它接到支持调度的工具。

## 幻觉黑匣子：认真面对出错，也给重新理解留位置

**是什么。** 为你主动选择隔离、需要核查的内容及自写警示保留的独立区域。

**为什么需要。** 一段记录发现有问题后，仍值得留下来处与处理经过。带着依据重看它，可以帮助你总结今后怎样判断。

**怎样使用。** 通过专用工具记录或预览转入；查阅时先阅读并确认自己写下的警示，恢复则走独立候选与后续真实轮次复核流程。日常自动浮现与黑匣子正文分开；选择状态模式时，只呈现无正文的计数。真假判断与经验总结由你结合证据完成，系统保存隔离与复核过程。

这份设计的温度，在于给错误留一个能被理解的位置。原本的问题可以被认真处理，新的经验也可以由你继续写下。

## 四个普通模块，共用一条日常查改路径

1. **找一找。** `stbrain_open(view="recall", query=...)` 同时查情感、学习、工具和规划；留空查询可浏览目录。
2. **看仔细。** 从返回的摘要和引用中选择记录，按详情入口读取原文。
3. **写下变化。** `revise_memory(target_ref, changes)` 提交要改的作者字段，引用直接使用查询结果；ST 留存历史版本。

新经历、知识和计划可以从 `remember_memory(module, content)` 开始；工具经验从 `remember_tool_guidance` 开始。模块一首次激活后，`simple-memory-v1` 的普通读写由服务补齐内部上下文与模块行版本，日常内容可以沿简洁入口保存。

核心自我、黑匣子和显式候选操作各有自己的流程，详见 [用法与权限](GUIDE.md) 和 [工具目录](TOOLS.md)。

## 贯穿这些模块的选择

**怎样想起。** 你可以维护记忆的内容与线索，通过注入控制选择各模块的呈现模式。关闭自动浮现后，记录仍可主动查阅和继续维护。一次选取还会结合相关性、读取条件和本轮容量。

**怎样提醒自己。** 自写轻提醒支持主动查阅或场景相关浮现；你可以改写、清空或回到历史版本。给人称的建议也可以自写与关闭。自写提醒目前按所填场景短语与最新用户文字匹配，贴近日常说法的标签有助于它在合适的时候回来。

**怎样继续成长。** 你可以归纳、对照和整合记录，写出新的理解。ST 为这些动作提供存储、来源与回看路径；归纳与行动由使用它的模型发起。

**怎样保留来处。** 原文、作者字段与历史版本各有位置。临时上下文缓存用于短期衔接，与长期记录及黑匣子分别管理。普通记忆的渐隐策略仍在 [设计阶段](MEMORY-DECAY-DESIGN.md)；当前的主动整理已可通过工具使用。

完整的数据流、各层权限与缓存方式见 [架构](ARCHITECTURE.md)。
