# 网关修复与原图传输优化（2026-11-07，main）

本次同步已部署验证的网关改动。GitHub 正式发布包仍为 v0.2.2；这些源码更新尚未创建新的 Release。

## 已修改的行为

- 上游发送完整 SSE `[DONE]` 后及时完成当前响应，不再等 HTTP 连接 EOF；保留已接收数据的格式、工具参数及凭据边界检查。
- 工具续轮报错返回固定错误码和有限诊断，区分目录变化、调用 ID/顺序/批次不完整以及上下文丢失。目录差异日志只记录计数和工具名称 SHA-256，不记录参数、schema、工具结果或聊天内容。
- 支持 DeepSeek Files 原图复用：支持该能力的客户端先确认网关能力，再上传原始图片字节；每轮模型请求继续携带同一原图引用，减少重复 base64 传输。仅适用于固定 DeepSeek 官端 Files 接口，不向任意模型服务发送探测或图片。
- 图片引用按账号与模型路径校验、带有效期，缓存仅在进程内保存；缺图或失效不会静默丢图继续回复。首次能力发现和冷上传仍可能较慢。
- 将已验证的缓存资料布局和可打印 Unicode 模型名称支持一起同步，保持人类原始输入、记忆捕获及工具绑定边界。

## 验证范围

本次发布树在独立、仅回环网络的 Linux 环境运行 2726 项合成回归：运行时 982、MCP 612、网关 880、安装包装 252，零失败；1 项 Windows ACL 专项按平台条件跳过。没有使用私人记忆或模型 API 执行这些回归。

真实 Orbis 同窗口、每轮历史原图开启的短回复：Wi-Fi 复用后约 7.7 秒，官端对照约 9.1 秒；流量约 12.95 秒（网关记录 11.59 秒）。这是少量实测，缓存命中、网络和模型负载不同，不保证每次更快。首次能力发现与图片上传样本约 33 秒。

工具链长并不等于超过数量上限。客户端在同一生成中仍须冻结工具目录、参数结构及调用 ID；本次没有放宽目录一致性、越权或未知结果保护，也不会重放外部工具。

Orbis 局部重新生成遗漏三个工具的修复属于客户端，不包含在本 ST 源码中。新用户消息曾出现工具数 388→391 的个案尚未确定触发条件；第三方花园 MCP 的偶发中断也未复现，不能据此宣称所有 409 或 MCP 中断已解决。

## 升级

从发布包升级应沿用安装器及数据保留流程。已经通过 Linux 安装器部署的实例，必须按原安装生命周期完成旧实例的离线收尾并建立新源码完整性清单；不要直接覆盖正在运行的源码后重启。保留原配置、身份和数据库，详见 [安装说明](INSTALL.md) 与 [升级验证](UPDATE-VALIDATION.md)。手机端配套能力需使用包含本次图片引用实现的 Orbis 版本；旧客户端继续传原图。
