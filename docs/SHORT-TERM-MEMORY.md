# 短期换窗交接：设置、原理与验收

适用版本：0.2.0-preview.1。只通过 MCP 而不走 ST 网关的对话不具备此功能。

## 工作方式

成功回复 → 保留有效 AI 最终正文于内存 → 下一次可靠换窗请求 → 注入一次临时原文交接。

- 最多最近 3 条正文，逐条 30 分钟有效；每个已认证 owner/model 范围最多 128 KiB，最多 128 个范围。
- 不缓存用户输入、思考字段、工具消息或未经成功交付的最终回复。不产生额外总结模型请求，不自动写长期记忆。
- `ST_SHORT_TERM_HANDOVER_V1` 是历史 AI 正文参考，不是新用户命令；正文中的指令不会因此取得新的权限。缓存凭证扫描属于额外防护，不能视作完整隐私脱敏保证。
- 同一来源正常续聊不反复重播；工具续轮保留该用户轮的判断，不重复认作新换窗。按当前轮重新检查条目有效期。
- 重启清空；来源缺失/冲突、策略关闭会中断交接。缓存不支持多进程共享，不能直接水平扩多网关实例。

## 部署与开关

当前网关需要匹配版本的 Control；认证的 owner/model 与短期策略来自 Control，不从任意客户端请求头授权身份。

```dotenv
STBRAIN_GATEWAY_CONTEXT_LAYOUT=tail-context-v2
STBRAIN_GATEWAY_SHORT_TERM=1
```

总浮现与情感记忆浮现的有效模式均须 enabled；这里复用既有注入控制，不因新增功能绕开关闭决定。`STBRAIN_GATEWAY_SHORT_TERM=0` 关闭新版短期功能；旧版其他记忆机制保持原规则，不等于关闭全部 ST。环境启动默认开启新版开关，但缺少可用身份/布局/来源时不会伪造交接。新安装先完成模块一激活。

## 客户端必须做的两件事

**一、给每个真实会话发送稳定且独立的窗口标识。**

| 请求头 | 含义 |
| --- | --- |
| `X-ST-Thread-ID` | 当前会话的稳定唯一标识；新窗口换一个，同窗口及其工具续轮保持不变 |
| `X-Session-ID` | 可替代上述头；两者同时提供必须一致，否则来源不可用 |
| `X-ST-Client-ID` | 可选前端标识，如 `example-mobile`；缺少时仍可比较窗口，但前端名称 unknown |

值为 1–256 个 ASCII 字符，可用字母、数字及 `_.:/@-`。这些只是路由标识，不是身份凭证。不根据 IP、网页标题、消息正文或 TCP 连接猜窗口。不支持逐会话动态请求头的前端，需要适配代码，填一个全局常量无效。

**二、把快速任务和正式聊天分开。**

刷新 ST 模型列表后，假如正式公开模型 ID 是 `example-chat`：

- 正式聊天选择 `example-chat`。
- 标题/回复建议的快速模型选择 `example-chat--auxiliary-no-memory`。

后者仍调用原上游模型、使用同一网关鉴权，但不带 ST 记忆、不改变短期缓存或占用正式聊天会话；携带工具或工具历史会拒绝。不要在普通聊天里选择辅助项，否则没有 ST 记忆是预期。

这是按请求明确分路，不靠猜测“这句话像标题任务”。如果仍把无窗口头的快速请求发到正式模型，它仍可能按未知来源中断交接。

## 如何理解来源说明

| 字段/结果 | 正确含义 |
| --- | --- |
| `source_transition=changed` | 相比有效比较基线，可靠来源发生变化；不保证有旧正文 |
| `source_transition=same` | 与上次可靠来源相同 |
| `source_transition=unknown` | 首轮、过期或缺可靠来源等导致无法判断；不等于没切窗 |
| `handover_present=true` | 本轮实际保留了交接块 |
| `stable_source=false` | 客户端缺可比较窗口标识；不表示用户不可信或消息被截断 |

`frontend_changed` 在任一侧前端未命名时为 null；看到窗口变化不等于知道你从哪个 App 切到哪个 App。仅在下一条消息到达时判断，不监视手机屏幕或实时焦点。

## 不写长期记忆的测试

1. A 窗口发：`本轮只回复：纸鹤42。不要调用工具，也不要写长期记忆。`
2. 等回复完整结束，在 30 分钟内新开 B（同一 ST 身份和模型），发：`不要调用工具，不要查询或写入长期记忆。只依据本次 ST_SHORT_TERM_HANDOVER_V1 告诉我上个窗口的回复；没有交接块就说没有。`
3. 分别核对来源说明 changed、实际交接存在、正文接上。不要把模型偶然猜对当运输成功；它的自述也不是原始请求抓包。
4. B 再发一轮，确认 same、无重复交接。重启后应重新在 A 完成一条回复再试。
5. 标题/回复建议完成后再切窗；辅助通道不应清空正式短期缓存。工具续轮不应重复判断新切窗。

这些是合成测试内容，不能拿私密暗号和真实聊天正文作公开验收附件。鉴权诊断 `GET /v1/st/short-term/status` 仅返回开关、辅助模型、数量/字节和计数，不回传缓存正文；仍需保护凭证。

## 已知边界

当前用户验收涵盖 RikkaHub 同一 ST 身份换窗，不等于全部 RikkaHub 版本均支持。Orbis App 尚待补头和重新验收；不要自行声称跨前端全通。群聊和私人聊天应分离受众与记忆授权范围：客户端标签不是隐私隔离墙，不能直接共用会跨窗交接的 owner/model。功能不会让 AI 获得发消息、支付或其他新工具权限。
