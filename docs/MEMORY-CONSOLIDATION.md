# 普通记忆的时间线与自主整理

情感、学习、计划、工具四个脑都能自主整理。结果仍存回原脑，使用原有的修改、精确查询和浮现规则，没有额外的“总结记忆”审批流程。

先通过 `stbrain_tools(category="organize")` 查看入口，或直接调用：

```json
{"action":"memory_timelines","arguments":{"query":"几次吃糖葫芦的经历","include_content":true}}
```

`query` 可以省略，查看主题分组；`module` 可选一个脑；`refs` 可精确回查某条记忆及其归档来源。默认返回摘要，`include_content=true` 返回逐条原文。`offset`、`limit` 用于分页，返回 `next_offset`。

列表包含共同关键词、候选记忆引用、原始记录数、关联引用及数量、按事件时间排列的原文、当前摘要和其他字段差异。`time_basis` 明确区分情感来源时间 `source_timestamp`、计划开始时间 `start_at`、知识截至时间 `valid_as_of`；缺少时使用存入时间并标明，不从正文猜造事件日期。这些字段各有含义，并非全部代表事情已经发生。关键词和文本相似度负责分组；配置了本地语义模型时，主题查询也检索语义近似项，`semantic_status` 如实标出通道是否完成。分组是线索，不保证每条事实相同。

AI 选择同一脑中需要整理的来源，自己重新写摘要：

```json
{"action":"merge_memories","arguments":{
  "source_refs":["emotion://emmem_实际编号@1","emotion://emmem_另一个实际编号@2"],
  "summary":"一个月前……；一周前……；今天又……。这些经历之间的变化是……"
}}
```

只有来源和新摘要必填。摘要必须由 AI 写，不要求固定模板、人称、独立来源次数、记忆年龄或重要度；没有后续唤醒审核。引用可以不带版本；明确带版本时，如果原文已被其他操作修改，返回真实变更提示，避免归档 AI 尚未看到的版本。

`content` 可由 AI 重写；省略时系统按来源时间串联原文。`title` 可改学习、计划和工具记忆标题；情感脑延用原有摘要和关键词标题。`fields` 可提供原脑的其他作者字段。列表中的不可自动统一的标量差异由 AI 判断；未指定时沿用首条来源值，回执仍列出差异，随后可用普通修改工具调整。

系统自动完成：

- 合并全部关键词并去重，不限制关键词数量和长度。
- 情感记忆绑定的多条计划转到新记忆；合并计划时，其他情感记录也转绑新计划。
- 转移普通关系、原生学习/情感关系、计划依赖、工具链接、情绪标签、图片和关键词必浮现设置。相同外部关系去重，组内关系保存在原始记录中。
- 新记忆存入与原记录归档在同一事务内完成。发生实际写入错误时一起撤销，不留下半条结果或已归档但无总结的来源。
- 原文、版本和来源时间线保留。再次整理会展开最初记录，也保留之前 AI 整理的正文和摘要。

原记录归档后不再自动浮现，仍可按引用查询；新记录照常浮现、修改和再次整理。原有的可见范围、浮现策略、上下文预算仍由普通脑机制处理。自动提醒仅提示本轮同关键词命中超过三条的主题，AI 自行决定是否整理；不会代替 AI 合并或额外生成一轮。

普通正文写入放宽到 100 万字，摘要 6.4 万字，标题 4000 字；存入更长的内容不会自动扩大每轮浮现预算。来源历史不需要被塞进每轮上下文。工作脑、核心自我定义和隔离库各有原有用途，本入口处理上述四个普通记忆脑。

## 补录旧事与最近存入

“最近存入”始终按实际入库时间 `created_at` 倒序；11月23日补录10月10日和11月10日的旧事，两条都会出现在最近存入的位置，修改正文日期不改变此排序。

情感记忆的来源时间 `source_timestamp` 可以由 AI 在 `remember_emotional_memory` 中填写，或通过 `revise_memory` 的 `changes.source_timestamp` 修改。未填写时，原机制默认记录当时，因此补录旧事需要显式填写事情原来的日期，不能只把日期写进正文。此字段改变会影响主题时间线的先后，但不会重写 `created_at`。不知道确切时间时保留不确定说明，不编造精确日期。
