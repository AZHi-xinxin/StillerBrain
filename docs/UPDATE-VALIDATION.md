## 2026-09-18 后续补丁：内部控制请求不继承环境代理

使用者反馈：学校手机流量下，接近 300K 上下文的网关对话也很顺畅，并授权发布此前暂缓的修复。这是特定部署的使用者验收反馈，不是标准化测速；没有把整体改善归因为单一代码改动，也不承诺任意客户端、网络或上下文都达到相同速度。

在公开提交 `71a21a62e74632eceacb3e614a6dcc5ac9845b60` 之上，仅恢复 L36 的 `ControlClient` 默认 `httpx.Client(timeout=timeout, trust_env=False)`。host/human 内部控制请求均使用此构造器；模型上游客户端行为不变，显式传入的 Control 客户端原样复用。不改鉴权、错误处理、工具权限、记忆内容或 Tailscale 设置，本轮不重启本机/VPS。

新增 4 项合成回归覆盖：实际回环 HTTP 服务与代理陷阱（认证请求直达 Control，代理零请求）、无效环境代理不阻止构造、显式客户端/超时保留、内部 host/human 与模型上游配置隔离。定向 4 项全部通过；回归使用假凭证和临时回环服务，没有真实模型调用或生产写入。

此补丁在 Windows / CPython 3.14.6 重新运行完整网关组：425 项发现、424 项通过、1 项跳过（含上述 4 项，不能再叠加计算）。核心 `tests` 与 `mcp_server/tests` 本次未重跑，其下方结果仍是 2026-09-17 历史记录。首次新增测试使用的假 human token 不满足既有 32 字符校验，改正测试数据后定向及完整网关回归均通过，未放宽产品校验。

安装/包装组另重新运行 117 项：114 项通过、3 项按条件跳过（Windows 不适用的 POSIX 权限项及两项未启用的本机服务选测）。原 206 份冻结来源文件 SHA-256 全部一致；新增代理测试单独计数，当前公开树共 269 个文件，源码清单完整性检查通过。

兼容边界：`trust_env=False` 也不读取 `SSL_CERT_FILE` / `SSL_CERT_DIR`。标准安装的 Control 是回环 HTTP；自定义 HTTPS Control 如依赖私有 CA，需显式注入配置好的客户端。TLS 校验没有被关闭，模型上游的环境证书设置仍保持原有行为。参见 [HTTPX 环境变量说明](https://www.python-httpx.org/environment_variables/)。

## 如何复测

在仓库根使用对应平台虚拟环境：

```sh
python -B -m unittest discover -s tests -t .
python -B -m unittest discover -s mcp_server/tests -t .
python -B -m unittest discover -s rikkahub_gateway/tests -t .
python -B -m unittest discover -s packaging_tests
```

部分用例启动临时回环服务，适合在空闲开发环境执行。升级后应重连、刷新 MCP 目录，从新回合开始；默认 `/mcp` 不会自动切成日常档。

本版没有量化真实模型的固定 token 节省比例或网络加速比例。已记录的学校流量/长上下文使用者反馈不能扩展为所有网络问题都已修复。目录体积、模型计费、缓存命中与实际响应时间是分别需要测量的指标。
