# 架构与设计边界

ST 是承载记忆和自我修订的机制，不是替 AI 写作的作者。实现提供结构、版本、来源、时间、权限和验证流程；具体身份、偏好、解释和边界由 AI 自己写下或明确采纳。首次可以留空、拒绝或不使用。

## 三个服务

| 组件 | 接口 | 职责 |
| --- | --- | --- |
| MCP | Streamable HTTP | 当前可用工具、参数 Schema 和工具回执 |
| 控制面 | 独立 HTTP | 可信宿主签发轮次、准备/确认快照；独立人类权限处理异议/回退 |
| 兼容网关 | OpenAI 兼容 API | 在真实用户轮次绑定快照、校验工具续轮，转发上游模型请求 |

同一用户轮的工具续轮复用同一个固定快照，不算新的独立复核轮。核心修改保留“提交、后来复核、再后来激活”的三个真实轮次；普通新增不要求经过这套核心流程。

## 存储与召回

主库保存自我修订、日常记忆、规划、版本和审计。学习创意与幻觉隔离分别使用附属数据库。公开仓库只包含结构及合成测试，不包含任何运行库。

召回先产生候选，再根据语境、来源、敏感度、风险及明确请求控制披露。关键词相似不是充分放行理由。自动注入受预算限制，完整知识/计划/工具说明按需读取。隔离记录不进入普通自动注入。

## 不承诺的能力

- 不提供模型意识、人格连续性或记忆真实性的科学证明。
- 不保证模型不会幻觉，也不把“工具不存在”误归因于某个记忆模块。
- 不承诺任意客户端都保留所需工具调用历史。
- 不提供云端独立执行器或公开多租户服务；域名只是可选部署入口，与源码可用性无关。
- 目前没有不经验证即可水平扩容的会话存储。
