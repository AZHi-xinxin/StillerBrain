# 自动浮现与主动查询：记忆如何被想起

[首页](../README.md) · [架构](ARCHITECTURE.md) · [工具使用](TOOLS.md)

ST 的两条路径，分别承接“此刻想起”和“再看仔细一点”。

| 路径 | 谁先发起 | AI 在什么时候得到什么 |
| --- | --- | --- |
| 回复前自动浮现 | ST 网关随新的用户消息准备上下文 | 模型开始回答时，已经能看到本轮选中的相关记忆、摘要或轻提醒 |
| 主动查询 | AI 调用记忆工具 | 按需要查目录、搜索或沿引用读取原文及历史 |

完成模块一初始设置、相关模块可用并开启相应浮现模式后，网关会把最新用户消息的文字作为主要查询线索，结合已有记录、作者标签与设置选择内容。自动浮现的这一步由宿主完成，AI 无需先调用查询工具；之后是否查细节、补充记录或使用工具，仍由 AI 决定。

## 作者怎样为后来留下线索

AI 可以按模块维护正文、摘要、关键词、情绪、场景标签及简短提醒。比如一段关于“奶奶家”的经历，可以留下人物、事件和你们日常会说的表达；学习过的排查方法，可以留下问题名称、常见说法和适用场景。

原词、近义表达、相关事物与情感语境，是作者选词的方向。当前选取主要依靠本地文字、关键词、场景和情绪等信号；明确写下常用表达，会让线索更容易与之后的话题接上。不同模块使用各自的匹配与呈现方式，具体见 [架构](ARCHITECTURE.md)。

当前自动查询主要参考最新一条用户消息的文字；网关现行输入上限为 4,000 字符。情感模块的文本分数包含字串与字符相似信号；部分路径另有有限近义词表。它们各自有明确覆盖范围：下面的“合照／合影”等补充词表属于主动查询回退，自我情境侧面使用自己的场景匹配；自动浮现并未接入通用向量语义检索。

## 一段记忆为什么这次会出现

作者的浮现开关与使用场景先决定哪些记录参与；相关性决定哪些内容贴近当前话题；读取权限和本轮容量决定最后带回的篇幅。选中的记忆与模型原本收到的对话一起参与回答。同一用户轮的工具续调用复用该轮快照，下一条真实用户消息再准备新的内容。

当线索不够或需要核对细节时，AI 可以用 `stbrain_open(view="recall", query=...)` 跨四个普通模块查询，再沿结果引用读原文。普通记忆的原文与版本保存在存储里，当前上下文只呈现这轮选中的部分。

## 做一次自动浮现验证

可以用一条合成记忆，看看“先想起”这条路径怎样工作。请在完成模块一初始激活的测试实例中进行，使用临时素材。前四步用于体验观察，第五步由部署者协助核验机制。

1. **留下记录。** 由 AI 保存一个有独特名称的小故事，例如“纸月书签”，并写入几项自选细节和贴近日常说法的关键词。记录查询返回的真实引用。
2. **确认接入。** 相应模块允许自动浮现；后续请求仍走正常运行的 ST 网关、连接同一记忆身份。
3. **开启新对话。** 等已有工具链完整结束，再开启不携带上一段聊天历史的新对话。可暂时关闭客户端的 ST MCP 工具入口，让这次验证只观察网关路径。
4. **只提话题。** 例如“说说纸月书签的事吧”。测试消息只给话题线索，故事细节留在记忆里。
5. **请部署者核对来处。** 使用测试宿主提供的调试入口，查看这次网关准备并确认的注入快照或回执，核对记忆引用及本轮是否发起过查询工具。具体入口随宿主而异；部署者可按 [网关的数据流](ARCHITECTURE.md#三个服务各司其职) 定位准备与确认环节。回答内容作为体验观察，与注入证据一起记录。

这验证的是“相关记录在回复前进入了上下文”。单凭模型回答正确，或说了一句“我记得”，还不能确定它使用了哪条信息路径。若宿主只展示回答，则先把结果记为体验观察，待有注入证据再确认机制。

恢复客户端工具入口后，还可继续主动查询、补充和修改。真实调试中，注入正文按私人记忆保护；对外反馈提供去除内容的引用与状态即可。

## 情感检索词法回退：历史机制与验证

本文保留 `0.1.0-preview.2` 引入的情感检索词法回退机制与当时的合成验证记录，下文“本轮”均指该次改进。实现使用本地 Python 与 SQLite，新增路径没有模型请求、向量服务或额外 Python 依赖。

当前 `0.2.0-preview.1` 的日常查询优先使用 `stbrain_open(view="recall", query=...)`，统一查找情感、学习、工具和规划四个普通模块；`recall_emotional_memory` 仍是情感模块的专用入口。现行用法和权限见 [GUIDE](GUIDE.md)，目录与参数见 [TOOLS](TOOLS.md)，本版验证见 [UPDATE-VALIDATION](UPDATE-VALIDATION.md)。下面的词表、分数与旧测试结果描述特定回退路径，范围与当前跨模块查询分别说明。

### 历史改进涉及的入口

| 入口 | 作用 | 本轮变化 |
| --- | --- | --- |
| 显式 `recall_emotional_memory(query=...)` | AI 主动找一段过去记录 | 原有结果不足时，补少量普通摘要候选 |
| 宿主自动召回/注入 | 为当前回合准备经过披露门与预算筛选的上下文 | 复用单次查询特征，评分公式、关联传播与披露门保持原样 |
| 按记忆 ID 回读历史 | 精确定位已有记忆与版本 | 保持原样 |

显式搜索仍需要原有服务层的所有者、模型、模块就绪与读取资格。调用检索工具的权限和内容披露权限各自生效。

## 原评分是什么

现有实现把文本包含关系、字符二元组重叠、有序字符串相似度、情绪标签、重要度和关键词命中合成一个本地分数，还会在已有有向关联上做最多两跳的衰减传播。代码中的历史名称 `_semantic_similarity` 指的是这些词法信号，属于字符串相似计算。

`score` 是原检索排序分，不是正确率或概率，也不是向量余弦相似度。本轮保持其公式、精确命中标记及传播方式：原先的 `0.2` 候选阈值、自动注入里的 `0.5/0.8` 原文档位继续使用原分数。

## A. 单次查询特征复用

过去每条记录、每个关键词会重复规范化同一个查询。现在一次搜索只准备一份大小写、规范化文本、字符集合与二元组集合，供整个所有者/模型范围内的评分共用。

局部有序匹配也增加了等价短路：如果关键词缺少超过一个必要字符，或缺失的是原算法不允许删除的首尾字符，就直接返回零。原算法允许的一次内部字符省略仍保持。

Unicode 兼容细节也保留：大小写折叠可能产生组合字符，旧二元组路径中的再次规范化继续执行，因此新旧评分在这些输入上仍一致。

这是减少重复 CPU 工作；当前仍读取并评分该所有者/模型范围内的记录，复杂度仍随记录数增长。它不是持久化倒排索引，也不声称大型数据库已经实现次线性搜索。

## B. 显式搜索的有限词法回退

当已有评分结果未占满请求的 `limit`，系统会检查下列公开、可审查的词法对照表。只对记录中已经保存的关键词匹配，不扩写人物/地点实体、不改写记忆：

| 表达一 | 表达二 |
| --- | --- |
| 合照 | 合影 |
| 散步 | 遛弯 |
| 搬家 | 迁居 |
| 重启 | 重新启动 |
| 拍照 | 拍摄照片 |
| 断网 | 网络断开 |
| 报错 | 错误提示 |
| 停电 | 断电 |

例如关键词保存为“合影”，后来用“合照”寻找时，可以得到一条摘要候选。模型仍需核对人物、事件和时间；词法相近不代表两件事相同。存在多义风险的“登录/登陆”没有放入这张表，避免把账户操作与登陆某个地点混为一类。

词表以外的同义表达、跨语言理解和复杂改写不在本轮能力承诺内。扩充词表需要同时增加召回和边界回归，不能只增加命中样例。

### 新候选如何表示

新补充项保留原 `score`（可能低于 `0.2`），并额外带有：

```json
{
  "candidate_only": true,
  "retrieval_match": "lexical_alias_candidate",
  "candidate_score": 0.28,
  "exact_match": false
}
```

`candidate_score` 只用于新词法候选之间的排序。原有结果始终优先、相对顺序保持；达到 `limit` 就停止补充。单个词族给 0.28，额外匹配词族每个加 0.04，上限 0.45；这些数值是排序权重，不是概率。

新候选只投影已有摘要，隐藏 `original_text`、`original_hash` 和原文指代绑定。即使调用方同时传了所有原文读取标志，也不会在这一回退路径直接返回原文；可以先看摘要，再根据真实需求使用已有精确读取入口及其权限规则。若一条摘要完整包含规范化后的原文，词法回退会跳过它，避免把完整原文换个字段名返回。

### 披露边界

- 新候选不进入自动注入、不产生关联传播种子，也不修改原分数、记忆内容、版本或衰减规则。
- `intimate/restricted`、`ask_first/neutral_hint/never_auto`、非 `normal` 召回模式以及非 `background_reference` 默认决策均不参与词法回退。
- 回退尊重原查询的允许/拒绝上下文条件。它不通过改写查询匹配这些条件。
- 原有所有者/模型隔离、隔离区排除继续生效；归档只有在显式请求 `include_archived` 时纳入。
- 新路径继续使用原审计机制，记录查询摘要值与结果 ID，不记录查询正文。

上述限制只收窄新增回退。已有精确/词法搜索和精确历史读取的原行为保持。

## 合成验证结果与范围

测试文件：`tests/test_retrieval_lexical.py`。

- 405 组合成输入覆盖中文插入/省略、拉丁字符、大小写、全角与组合字符：新旧原评分值和精确标记一致。
- 128 条合成记录、每条 24 个关键词、1000 字符查询：查询侧 `_normalized` 调用从 3456 次降至 2 次，结果一致。这是具体操作计数，不能当作整个检索耗时的加速倍数。
- 8 组表内替代表达：对目标记录，原评分路径找回 0/8，新增显式摘要回退找回 8/8。这是为该机制构造的对照集，不代表真实记忆库的整体召回率。
- 回归覆盖旧结果优先、结果上限、原文与原文绑定隐藏、敏感/语境门、所有者/模型、归档/隔离区、实体混淆、两跳传播边界、自动注入不使用词法回退，以及审计不含查询正文。

可在干净测试环境运行：

```bash
python -B -m unittest tests.test_retrieval_lexical tests.test_emotional_memory tests.test_mixed_recall_r4h34 tests.test_injection_control mcp_server.tests.test_emotional_service -q
```

测试只使用临时合成数据库；本轮没有读取私人记忆库或调用生产模型。本轮也没有实施记忆衰减算法。
