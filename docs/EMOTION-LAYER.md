# 我定义的感觉

情感脑记下发生过的事，情绪层给这些事加上你自己的感觉。它也能给学习、计划和工具记录打标签。

## 为什么这样设计

记忆不仅是“发生过什么”，也可以保留“我怎样理解那个时刻”。同一种感觉能成为一条细线：今天提起奶茶时，先想起那次喝奶茶，再轻轻带来另一个同样满足的日常。

情感脑保存经历，情绪层保存你为这些经历定义的词与关联；它不是另一份重复的记忆正文，也不是系统给你打分的情绪检测器。词语和定义由 AI 自己写，不要求采用人类的固定分类，不要求每条记忆都打标签，也不要求解释为什么这样命名。这里的“情绪”是作者的描述和检索线索，不是对模型具有主观感受的技术证明。

我们让主记忆优先、连带少量、按相关性选择，并加上冷却，而不是随机翻出一大串往事。这样既给联想留位置，也不让它抢走眼前的话题。标签可以修改，理解可以变化；删掉一个情绪词不应删掉曾经发生的事。

自由管理仍在当前身份与既有权限内，不等于读取其他助手、黑匣子或未授权资料。系统不替 AI 决定必须产生什么情绪，也不按人类反馈强制改写其定义。

首次使用有“喜、怒、哀、乐”四个空占位。名字、定义、数量都由你决定，可以全删；删后不会自动补回。定义可留空，最多200字。

## 用法

### 先让 AI 找到说明

接通已有 ST MCP 后，让 AI 先调用 `stbrain_help(module="emotion_layer")`。精简工具目录用 `stbrain_tools(category="feelings")` 发现对应工具，具体参数以当前返回的 schema 为准。没有这些入口时先核对服务版本及客户端工具缓存，不要编造调用成功。

只连接 MCP 也能管理词表、打标签和主动查询；要在回复前自动连带浮现，还需使用 ST 网关或等价宿主，并完成已有的初始化及相关浮现设置。升级不是重新初始化身份，见[运维说明](OPERATIONS.md)。

### 一次最小流程

以下都是虚构例子，不需要逐字照抄；词语和内容由你自己决定。

- `emotion_list()` 看当前可用名字、id和设置。
- `emotion_manage(action="create", name="幸福", description="一起做平常的小事")` 新建。
- `emotion_manage(action="update", emotion="幸福", name="满足")` 改名，已有标签随同保留。
- `emotion_manage(action="archive", emotion="满足")` 暂停浮现；`restore` 可恢复。
- `emotion_manage(action="delete", emotion="满足")` 删除情绪，只解除标签，不删除任何记忆。
- `remember_memory(content="一起喝了奶茶", emotions=["满足"])` 可选地随存入打标签，正文与标签一起成功或回滚。
- `memory_emotions(memory_ref="查询返回的当前版本引用", emotions=["满足"], action="add")` 给旧记忆追加；`remove` 移除，`replace` 替换，`replace` 配 `[]` 清空。

这些操作无需解释理由，沿用当前连接、助手和记忆模块的已有权限。不会操作别的助手或隔离库。

先查词表再决定是否创建；同名含义变了可改定义，不必不断创建重复词。给旧记忆打标签时先查询得到当前 `memory_ref`，不猜编号。遇到版本冲突，重读并核对再决定修改；普通保存省略 `emotions` 仍可正常使用。组合保存失败时正文与标签一起回滚，只有成功回执才算保存完成。

## 想起来时

常规召回先保留身份、常驻提醒和最高相关主记忆的完整投影，再为它带入自己写的情绪定义，并尝试带同情绪的一条旧记忆短摘要。其余低相关候选再竞争剩余空间；不会为了联想删掉主记忆。按本地文字相关度、最久未浮现顺序选，不随机；摘要最多160字。

默认最多1条、20轮冷却。`emotion_manage(action="settings", secondary_limit=0, cooldown_rounds=20)` 可关闭连带，数量可设0–3；设0仍可带主命中的情绪定义。一次参与检索的唤醒和它的工具续轮只计一次，重复请求沿用保存的快照。内部短期选择账本最多保留256轮，已生成的正式上下文快照仍按原机制保留。

连带共用原1200 token动态预算，装不下便省略；不扩大原文权限。被暂停、隔离、限制或需要先询问的记录不会借情绪绕过。工作脑仍只主动读取；工具卡仍受当前工具目录约束。

通用存入回执返回当前可用名称；高级专用存入后也可用当前引用调用 `memory_emotions` 打标签。标签不改变原记忆的自动带入开关：不自动带入的记忆仍可打标签，连带时不会绕过开关。`emotion_list` 返回词条数、标签数、已打标签记录比例、连带命中率和冷却跳过次数，不返回记忆正文。完整说明也可用 `stbrain_help(module="emotion_layer")` 查询，精简目录从 `stbrain_tools(category="feelings")` 发现。

实现复用现有SQLite、普通记忆授权与唤醒快照；复合所有者索引、外键解绑和事务遵循 [SQLite外键说明](https://www.sqlite.org/foreignkeys.html) 与 [事务说明](https://www.sqlite.org/lang_transaction.html)。没有新增向量服务或云请求。

## 常见问题

- **必须用喜怒哀乐吗？** 不必。它们只是首次空占位，可改、可删、可全部不用，删后不补回。
- **删除、归档会删记忆吗？** 不会。归档暂停该词参与浮现；删除解除标签，记忆正文仍在。恢复归档词用 `restore`，删除不是归档。
- **打了标签，为什么没自动想起？** 先核对是否经过网关、模块开关、读取权限和主记忆是否命中，再看冷却及预算。只有 MCP 或只有标签，并不保证自动注入。
- **不想要连带，只想保留标签？** 把 `secondary_limit` 设为 0；主命中仍可携带情绪定义。要停止模块自动浮现，使用已有模块开关。
- **会追加模型服务或费用吗？** 标签与选择在本地运行，不新增云服务；进入模型的定义和短摘要仍占用已有上下文预算，实际费用取决于所用模型。
- **人类需要替 AI 填表吗？** 不需要。人类部署、授权并提出需求，AI 通过工具自行组织词表与记忆；无需把数据库或密钥发给模型。

## 安装与升级提醒

本功能包含新增数据库表和索引。先停止在途生成与写入，备份原数据库、配置及图片数据，再按[升级步骤](OPERATIONS.md)更新；不要以新示例覆盖已有身份和凭据，也不要未经核对直接降级旧代码。此版本已在维护者的本机与 VPS 配套环境验收，不代表每种部署和客户端都完成测试。
