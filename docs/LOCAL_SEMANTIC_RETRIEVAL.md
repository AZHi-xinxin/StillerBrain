# 可选本地语义检索

这份开发改动补充“换一种说法也能成为候选”的路径，不改变记忆正文、版本、归档状态或作者的浮现设置。默认不启用，不要求已有部署下载模型；开启后使用 CPU 上的本地 BGE 中文小模型，不把记忆送到外部嵌入接口。

## 覆盖范围

| 路径 | 本次覆盖 |
| --- | --- |
| 情景记忆自动浮现、主动 query 查询 | 现有词法结果 + 独立语义候选；仅靠语义找到的新项只展示摘要 |
| `stbrain_open(view="recall", query=...)` 统一查询 | 情景记忆分支接入相同语义摘要通道；空 query 的全目录不启动编码。其他三个分支仍为词法检索 |
| 学习记忆、规划、工具说明自动浮现 | 现有规则 + 对合格摘要的独立语义候选 |
| 学习、规划、工具的主动 query 查询 | 暂保留既有词法路径；不宣称已经全部向量化 |
| 精确引用、版本读取、作者已有关系 | 保持原行为 |
| 原文深处未出现在摘要里的细节、指代消解 | 本次不覆盖，不等同“全库任意细节都能想起” |

语义相近只说明可能相关，不能确认同一人、同一时间、同一事件，也不会自动合并或连边。情景新候选不会触发原文披露，也不作为现有关系传播的起点。规划的到期优先级仍在，不新增按年龄遗忘。

## 安装和开启

在独立测试环境先安装核心依赖及 `requirements-semantic.txt`。运行 `python scripts/prepare_semantic_model.py --cache-dir <源码目录外的模型缓存绝对路径>`，该步骤会联网下载公共模型，只用合成短句预热。

将输出的模型目录写入私有服务配置：

```text
STBRAIN_SEMANTIC_MODEL_DIR=<已下载模型的绝对目录>
STBRAIN_SEMANTIC_INDEX_DIR=<私有派生索引的绝对目录>
```

两个配置缺任意一个即关闭。需要使用语义检索的服务进程必须使用装好可选依赖的环境并读取相同配置；`scripts/run_component.py` 会传递这些字段。运行期指定 `local_files_only=True` 与本地模型路径，不自动下载、更新模型。删除两个配置并重启服务即可回到原检索；**不删除业务数据库**。

模型为 `BAAI/bge-small-zh-v1.5`，可选依赖 FastEmbed 0.9.0。模型及依赖的安装平台支持需分别验证，不能把 Windows 验证当成 Termux、Android 或鸿蒙验证。[FastEmbed 模型目录](https://qdrant.github.io/fastembed/examples/Supported_Models/)

## 候选、优先级与容量

每个模块先按原有身份、状态、场景和展示规则产生可参与的当前摘要，再做词法检索与独立向量相似度检索。向量通道默认余弦阈值 0.50，最多 5 项；不是固定凑满 5 项。该阈值为开发起点，不能代表已在用户数据上标定。最初 0.60 在四条合成改写上均漏召回，调整后其中三条进入候选，一条仍未召回；不因此宣称解决任意换说法。

语义候选排序提示为 `0.5 + 0.3 × cosine`，与已有相关性分数取较高值或独立补候选；**它是排序提示，不是事实置信度，也不是 RRF**。强字面命中保留原有优先级。情景模块已有词法候选不会因语义分而扩大原文权限。

原模块条数上限和 1,200 token 共享容量不变。“进入候选”与“实际进入上下文”分开记录：宿主 `prepare_context` 审计的 `retrieval_selection` 包含各模块候选数、选中数、容量拒绝尝试数、模块配额跳过数和最终估算容量，不记录查询原句。容量拒绝尝试可能包含摘要升级、附加提醒，因此不等于独立漏掉的记忆数；最终注入快照仍是交付证据。

## 索引与故障回退

索引只保存向量、哈希引用及内容摘要哈希，不保存正文、摘要或查询原文；向量仍是私人派生数据，目录权限和备份按私人记忆对待。不同业务库路径、owner、model、模块、模型文件签名隔离。当前内容或版本变化就重算；查询只使用本次合格快照中的引用，已删、归档或关闭的旧向量不能从缓存复活。

向量以 little-endian float32 BLOB 保存，读取检查长度、归一化范数和维度；索引格式版本进入命名空间。开发阶段从 JSON 向量改为该格式，避免每次查询大量解析数字文本；旧派生索引不会被当成新格式读取。

后台单工作线程逐批更新索引。自动浮现冷启动立即回退词法，已热状态每通道最多等待 150 毫秒；统一主动查询的情景分支允许等待首次结果，等待事件最多 2 秒（不等同整个工具调用耗时上限）。超时继续回退，不无限等待。队列最多 8 个不同请求、完成缓存最多 16 个。单模块合格摘要超过 4,096 条时明确降级，不静默截断成“已检索全库”。每摘要最多编码 1,600 字符，模型还有自身 token 上限。

统一查询返回 `semantic_status`，列明本次接入语义的模块及状态；未接入的三个模块不会冒充 `ready`。`retrieval_complete` 表示本次启用的检索通道完成且模块读取无错误，不表示任意相关记忆都能找全。语义降级时 `retrieval_complete`、`exhaustive` 均为 false，即使词法返回零条；`partial` 继续只描述原有模块读取错误。`disabled` 表示未配置语义，仍可以完成原有词法查询。语义通道完成状态变化会使旧分页 cursor 失效，重新查询，防止跨两套结果漏页或重复。独立情景 query 返回零条时也保留 `semantic_backend_*` 原因码与审计证据。

重建时停止相关服务后移走派生索引目录，保留业务数据库及模型，再开启服务即可重建。旧模型命名空间文件不会自行批量清理。索引不是原始记忆备份，也不承诺磁盘擦除；被删除或不再合格的条目不会被命中，但清理全部旧派生文件需单独操作。

状态为 disabled / empty / ready，或带 `lexical_fallback` 的 indexing、busy、unavailable、invalid_configuration、corpus_limit 等。冷启动回退不表示记忆不存在；同一用户轮仍遵守快照复用，不在工具续轮偷偷替换注入。

## 验收与后续

运行 `python -B -m unittest tests.test_semantic_retrieval tests.test_unified_semantic_recall mcp_server.tests.test_unified_recall_transport -v`。合成测试覆盖摘要改写通道、真实注册入口路由、版本失效、删除、作用域隔离、未关闭数据库、队列上限、故障回退、原文不变、等待上限、状态可见、分页失效及预算诊断。实际中文模型效果和耗时另行记录，不能由假编码器测试替代。

部署前仍需：脱敏的正例/近似反例/无答案集、真实主机冷启动与热查询延迟、恢复索引、四模块实际注入证据。后续可完善其他主动查询路径、中文阈值标定及显式关系的一跳摘要辅助；不进行全库自动连边或自动归并。

2026-10-16 在独立 Windows CPU 环境中，用校验过的 Qdrant ONNX 模型和八条合成摘要完成真实模型冒烟测试，运行期间拦截 socket.connect。无关天文问题未命中，但“另一个人看病”仍会找到相似看病经历；否定问句也可能带出另一人的咖啡偏好。这是已知精度限制，候选绝不能被当成事实答案。没有读用户库、没有生产部署，也不能把八条样例包装成总体准确率。

本轮比较了原始查询与官方建议的检索前缀，在这些样例上原始查询更合适，因此暂保留原始查询；这不是普遍模型结论。[BGE 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)

700 条合成摘要容量冒烟：该开发机初次建索引约 4.77 秒，后续直接查询约 56–58 毫秒，worker 热查询约 60 毫秒且命中目标。早期 JSON 格式约 204–208 毫秒，超过等待窗口导致降级；BLOB 格式修正了本样例问题。这些是单机单次测量，不是平均延迟或生产 SLA；样例含大量重复的无关描述，不能代表 700 条真实复杂记忆的质量和冷建库耗时。
