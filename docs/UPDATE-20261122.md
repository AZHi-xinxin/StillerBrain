# 2026-11-22 · 关键词必浮现与现用版本同步

这次 main 同步维护者当前实际运行的 ST，源码标识为 `0.2.5-dev.20261122`。维护者与所属 AI 已实际验证十条关键词必浮现记忆可用。GitHub Release 的最近正式版仍为 `v0.2.4`；本页介绍 main 新增的内容。

## 这次可以做什么

- **给选定记忆设置关键词必浮现。** 普通四脑合计最多十条，由所属 AI 选择开启或关闭。匹配当前新人类消息中的明确关键词，优先带入该条允许展示的简短摘要；原记忆正文、重要度和衰减不被改写。默认关闭，第十一条不会挤掉已有设置。详细匹配、预算和计数说明见[关键词必浮现](FORCE-RECALL.md)。
- **浮现提示更短，查询仍能取到完整信息。** 上下文使用简短摘要与短编号；来源、可信度和披露详情放到 AI 实际查询的工具返回里。支持以短编号精确读取对应记忆，原完整引用继续可用。真正切换窗口或模型时仍提供简短交接提示，同窗不会反复加入来源说明。
- **AI 可以直接维护自己的定义。** 模块一的初次建立和后续修改支持直接写入，原来的提案流程仍可使用；移除固定正文、标签和理由长度限制，以及对普通文字的词面误判。身份、模块归属和实际执行授权仍由各自接口处理。
- **修复工具参数错误导致整轮中断。** 默认原生分发模式下，模型生成的无效 JSON 等参数错误可以交给客户端形成工具错误结果，模型随后继续处理；ST 不把无效参数当成成功执行，也不自动重做旧工具。

## 怎样开始使用关键词必浮现

连接已更新的 ST 网关及 MCP 后，可直接告诉 AI：把你选定的几条记忆设为关键词命中时必浮现。AI 可调用 `stbrain_tools(category="force_recall")` 查看说明，再通过 `stbrain_manage(action="memory_force_recall", arguments={...})` 管理开启、关闭、查询和列表。

关键词沿用记忆中保存的词句。只接 MCP 而没有接通 ST 网关注入，不会在聊天前自动浮现；工具续轮、历史消息、AI 自己的回复和哨兵不会冒充本轮新人类关键词。原有禁召、模块开关和披露选择仍有效。十条是可开启的数量，实际注入还受既有上下文预算约束；工具会区分“命中”和“实际注入”，不会把未放入上下文的内容记成已成功浮现。

## 更新已有实例

本次源码在 main；下载旧 `v0.2.4` Release 不会取得本页新增功能。取得 main 后，按原部署方式整体更新 Gateway、Control 与 Runtime，保留真实配置、数据目录及 owner/model 身份。核对实际服务的启动目录，确保重启的是更新后的实例。

本版首次使用关键词必浮现时会建立三张元数据表：`memory_force_recall`、`memory_force_recall_history` 和 `memory_force_recall_receipts`，保存开关、历史及命中回执，不重写原记忆正文。升级数据前保留可恢复副本；源码中的示例配置不能覆盖真实配置。

公开版继续使用 `STBRAIN_CLAUDE_CACHE_ROUTES_JSON` 配置可选 Claude 兼容路由。运行实例里的私人供应商地址未进入源码，原公开配置方式保持可用。
