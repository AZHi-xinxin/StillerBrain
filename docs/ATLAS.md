# 星图：从 Orbis 连接 ST，只读看见记忆结构

星图只展示 `atlas.metadata.read` 范围的匿名节点、模块类型、保存时间和节点关系。它不返回记忆正文、标题、关系备注、人格、聊天记录或凭证，也不调用模型。默认可登记设备不等于匿名开放：登记仍需网关认证，读取与撤销使用独立的设备令牌。

## Orbis 中怎样连接

此版 ST 已包含配套星图接口。使用支持 ST 星图授权的 Orbis，在星图连接设置中选“使用已有 ST 连接”，选择已有的 **ST 模型网关**，按界面完成只读授权，再刷新即可读取真实星点；不必把记忆导出成文件，也不必让 AI 调工具搬一份记忆到手机。客户端会登记独立设备令牌，不要求用户把服务器的内部 ID key 填进手机。

所选连接须为已启用的、单密钥 OpenAI 兼容 ST 网关连接，地址使用网关根地址或 `/v1`；**不能选择仅有的 `/mcp` 地址、MCP Token 或官方模型直连配置。** ST 网关还须已启用星图设备登记。复用现有连接不表示拿上游模型 API Key 当星图令牌；若提示未启用，先按下文核对服务器配置，不要用普通 MCP 凭证直接读快照。

配套 Orbis 的真实连接、点选星点查看类型/时间、退出重开及刷新已由使用者验收。它仍是匿名结构视图，不是记忆正文阅读器；工作记忆和图片原件不进入星图。参考银河图片的美术重做不是本版功能。

供宿主适配的网关路径为 `GET /v1/st/atlas/capabilities`、`POST /v1/st/atlas/grants`、`GET /v1/atlas`、`POST /v1/st/atlas/grants/revoke`。这些是固定范围 HTTP 协议，不是新增的模型 MCP 工具。其他前端需要自行实现设备授权和图谱显示，不能只因 ST 升级就视作已有界面。

## 新安装

本版 `scripts/install_stiller.py` 为**新建的安装**生成完整配置：

- `STBRAIN_ATLAS_BOOTSTRAP_ENABLED=1`；
- 独立随机的 `STBRAIN_ATLAS_ID_KEY`，64 位小写十六进制；
- `STBRAIN_ATLAS_FORBIDDEN_VERIFIERS_JSON`，包含本次生成的五种 ST 通道凭证、上游 API Key，以及 ID key 文本的 SHA-256 摘要。

ID key 不从其他凭证派生，也不会在启动时重新生成。完整配置只存私有 `config.env`，不要把 key 或禁止摘要列表复制到客户端、反馈或 Git 仓库。客户端自行创建符合协议的独立设备令牌；不得复用网关、MCP 或模型 API Key。

控制面首次带完整启用配置启动时，在现有主库创建星图授权表；不新建另一份记忆数据库，不改记忆正文。是否能在客户端看到星图还取决于客户端适配，不代表任意 OpenAI/MCP 客户端都已有星图 UI。

## 已有安装：不会静默启用或换密钥

三个星图字段都缺失的旧配置，继续按旧行为关闭，不访问星图表或生成 key。仅显式设置 `STBRAIN_ATLAS_BOOTSTRAP_ENABLED=0` 也保持关闭；原来完整的一组 `0 + key + 禁止列表` 同样保持关闭。重新运行安装向导继续旧安装，不会补写这些字段。

`1` 搭配缺失/无效的 key、无效摘要列表或不完整配置会拒绝启动，不能靠删字段或随机换 key 处理。原 ID key 丢失时，优先从私有配置备份恢复，否则原匿名节点身份可能变化。

### 只生成升级候选

下面命令**不应用配置、不停止或启动服务、不备份或改写数据库**。它只读取指定配置；原先缺 key 时，额外查询主库的 `sqlite_schema` 是否已有星图授权对象，不查询记忆记录。SQLite 以只读 immutable 模式打开；非空 WAL/SHM/journal 会拒绝，以免遗漏尚未合并的 schema。

先正常进入该实例原有的维护流程，确认停止、保存原配置和三库的可靠备份，再准备候选。路径换成自己的；`--output` 必须是源码外**尚不存在**的目录：

```powershell
python -B scripts/prepare_atlas_config.py --config D:/ST-private/config.env --output D:/ST-atlas-candidate --enable
```

Linux 同理，使用实际 Python 命令与绝对路径，例如 `/home/your-user/ST-private/config.env` 和 `/home/your-user/ST-atlas-candidate`。

命令的规则：

- `--enable` 只允许给原来没有开关的配置生成启用候选，**不会覆盖显式 `0`**。改变明确的关闭选择需另行确认维护安排。
- 原配置、所有未知配置项、身份、数据库路径、端口、模型路由及已有有效 ID key 保留；只可能调整三个星图字段。完整旧配置的禁止摘要会与当前已配置的通道和路由凭证合并，旧摘要不删除。
- 缺少 ID key 但主库已有星图授权对象时拒绝生成替代 key，即使表为空。恢复原 key 后再准备候选。
- 禁止摘要上限为 32 个，超限拒绝，不截断。没有 `--enable` 时，缺字段的旧配置不自动开启。
- 输出目录应用私有权限后才保存 `config.env.candidate`，另存无秘密值的 `candidate.json`（原件与候选哈希、改动字段名、未应用状态）。只创建一次，不覆盖已有目录。
- 写入前后再次核对原配置未变。失败留下的不完整目录只作现场；没有完整回执的候选不可应用，不自动删除或重试。

这个命令不证明运行服务已停止，也不判断所有部署约束，更不会应用候选。**经原维护程序核对停止证明、备份、身份、源版本和候选哈希后，才由部署者批准应用。** 使用原生 lane/服务管理清单的实例还需更新它们自己的配置绑定；不能直接复制候选覆盖运行文件。应用后按原流程检查健康状态和星图 capabilities，再由客户端登记设备；不要用真实模型请求当健康检查。

已有配置写成了部分星图字段、原 key 不见了、数据库有非空日志或输出目录已存在时，先保留现场并核对；不要清数据库、删授权表、清 WAL 或关闭 TLS 校验来绕过提示。ID key/配置回滚和设备重新登记需单独维护确认，本命令没有验证或自动执行回滚。

## 管理路由新增密钥时

网关在每次星图登记、快照读取、撤销之前读取当前受保护凭证快照，并在 Control 返回后、交付响应前再核对一次。管理路由中新添或本进程保留的旧 API Key 不能借用为星图设备令牌；即使它碰巧符合 `orb_atlas_…` 的格式，也会拒绝。

该检查使用进程内管理存储快照，不读取模型内容。快照不可用时失败关闭，不退回旧列表。响应还按当前和请求开始时的秘密集合检查，且始终限制为固定元数据字段。管理更新与 Control 请求并非同一数据库事务；如果更新在请求中途发生，返回前会拒绝交付，新保护范围也会约束后续请求，不宣称分布式原子注册。
