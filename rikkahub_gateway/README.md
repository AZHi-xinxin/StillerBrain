# 生成前记忆注入网关

0.2 提供内存短期交接、`ST_SOURCE_V1` 来源变化说明及无记忆辅助模型；本次更新补充多模型路由、可选人类路由管理、非人类消息来源标记及独立工具尾段预算。配置、会话请求头、客户端快速模型选择和合成验收见 [短期换窗指南](../docs/SHORT-TERM-MEMORY.md)。短期功能本身不增加 MCP 工具，不监视屏幕，也不等于所有前端已适配。

这是一个 OpenAI 兼容的模型接入层。客户端仍使用原来的模型能力，ST 网关负责把当前记忆带到回复开始之前，并连接同一轮中的工具调用与结果。

## 一轮对话怎样经过网关

1. 新用户消息到达，网关向 ST 控制面申请真实轮次。
2. 运行时准备本轮稳定自我与相关记忆快照。
3. 网关按选定布局加入精确的 ST 消息，校验并确认注入。
4. 请求转发给原模型服务；普通思考和正文按流式协议逐步交付。
5. 工具调用通过本轮目录和参数校验后交给客户端，结果回到同一轮继续生成。
6. 普通回答完成或受控失败后结束该轮；下一条真实用户消息建立新快照。

已激活的自我与普通记忆各按设置参与上下文。核心编辑期间继续使用当前活动自我，候选材料通过对应工具主动读取。模块一的提交、后来复核与再后来激活仍是独立阶段。

## 客户端怎样填写

| 设置 | 内容 |
| --- | --- |
| 供应商类型 | OpenAI 兼容 |
| Base URL | 部署者提供的网关 HTTPS 地址，末尾 `/v1` |
| API Key | 独立的 `STBRAIN_GATEWAY_TOKEN` |
| 模型 ID | 部署配置的 `STBRAIN_GATEWAY_MODEL`，保留客户端识别模型能力所需的真实 ID |
| ST MCP | 单独连接对应 `/mcp` 地址与 MCP 凭证 |

临时别名可能影响客户端对工具、视觉等能力的识别，部署时应核对实际模型 ID 和客户端能力设置。上游地址和 API Key 保存在网关私有配置里；不要把上游密钥填成客户端的网关 Token。

流式输出可开启。思考设置、图片、原生 `tools` 与 `tool_choice` 按上游兼容契约传递；支持情况由实际模型与客户端共同决定。

## 缓存布局

`STBRAIN_GATEWAY_CONTEXT_LAYOUT` 支持：

| 值 | 布局 |
| --- | --- |
| `legacy` | 原兼容路径；源码在变量省略时采用此值 |
| `anchored-v1` | 稳定层前置，动态层绑定在本轮初始用户消息之前 |
| `tail-context-v2` | 稳定层前置，动态层置于本次客户端消息之后 |

新示例配置选择 `tail-context-v2`。它让较长聊天前缀保持稳定，同时把当前 ST 提示放在接近生成的位置。工具续轮复用同一份 ST 帧，当前客户端消息仍如实传递。旧配置省略变量时保留原布局。

缓存命中以供应商返回的 usage 为准。实际本地使用已收到命中改善的反馈；详细机制、观察方式与边界见 [CACHE](../docs/CACHE.md)。

## 工具调用与执行结果

网关从本轮客户端实际提供的工具目录建立名称与参数 Schema 哈希绑定。上游产生的整批工具调用经过完整重组、逐项参数验证和执行策略检查后统一释放；出现无效项时，该批工具保持未释放。

客户端应保留 MCP 参数 Schema，包括本地 `$defs` / `$ref` 及其约束，不能只拷贝顶层 `properties` 后删掉定义。网关按实际收到的目录验证，不会凭空补回客户端丢失的 Schema。刷新目录与完整工具续轮都应纳入客户端验收。

工具结果续轮沿用真实的调用 ID、名称和参数绑定。目录漂移、缺失或重复结果、跨轮混入与重放会得到明确失败。网关传输回执保存必要元数据；目标工具是否真正成功由实际执行器提供证据。作者在工具脑里填写的可信度与外部执行确认分开记录。

`X-ST-Thread-ID` 可提供额外的会话一致性检查。它与调用血缘共同工作；聊天正文、模型名和自填“执行绑定”字段都不是身份签发入口。

## 多模型路由与只读能力

原 `STBRAIN_GATEWAY_MODEL`、`STBRAIN_UPSTREAM_*` 继续定义默认路由。可选 `STBRAIN_GATEWAY_ROUTES_JSON` 添加最多 16 条额外路由；完整 JSON 不超过 64 KiB，密钥字段用 `api_key_env` 指向形如 `STBRAIN_UPSTREAM_ROUTE_EXAMPLE_API_KEY` 的独立环境变量，不在 JSON 内写明文 `api_key`。模型目录只公开模型 ID，不公开上游密钥。

显式未知模型会拒绝，不回落到默认上游。每次正式轮次固定已选路由，工具续轮不得中途切换；管理更新只影响之后的新轮次。需要通过独立人类界面添加/更新路由时，参阅 [人类路由管理](ROUTE_MANAGEMENT.md)：默认关闭，管理 Token 与聊天 Token 分离，不把该能力提供给模型。

鉴权接口 `GET /v1/models/<经过 URL 编码的公开模型 ID>/balance` 只为当前实现支持的官方 DeepSeek 上游提供余额查询；其他供应商或中转不承诺支持，不能把“不支持/未知”显示成余额为零，也不查询默认路由来冒充所选模型。此接口不生成聊天。

`/v1/models` 同时广告 `input_origin_contract=st-input-origin/1` 和 `busy_wait_contract=st-busy-before-generation/1`。客户端应先核对能力再启用对应交互；这些能力字符串不是认证凭证。

## 普通对话通路与非人类来源

咨询对端正文与平台唤醒可以作为明确标记的普通对话事件：设置 `X-ST-Source-Kind: consultation-peer` 或 `consultation-wake`，并提供稳定窗口标识及有效 `X-Request-ID`。省略来源头沿用普通人类消息路径。来源帧 `ST_INPUT_ORIGIN_V1` 明示 `human_authorization=false`；对端内容不因此成为人类授权。

该普通通路仍使用当前已认证的 ST 身份、记忆策略与已允许工具，不因隐藏聊天 UI 而另建无记忆身份。旧的 `X-ST-Execution-Profile: consultation-active-readonly` / `consultation-archiving` 是另一条受限通路，不捕获或注入这套 30 分钟短期交接，也不能与上述来源头混用。客户端仍须实现正文转发、窗口绑定、工具执行和结束/公开动作；模型在正文中写“可公开”或“结束”不等于 ST 已执行这些动作。

同一正式身份已有活跃轮次时，新轮可能返回 `human_turn_in_progress`。仅附带 `retry_class=busy_before_generation`、`generation_started=false`、`retry_after_ms=1000` 的特定响应表示尚未开始本次生成；客户端还应确认本地没有输出或工具执行证据，才可按自身有界等待策略保留同一待发事件。这不授权重放已输出轮次，也不适用于其他 409 或网络结果未知的请求。

## 失败怎样反馈

当前工具参数失败会尽量给出安全的错误码、工具名、公开字段和校验类型，帮助找到需要调整的位置。原始参数值、用户正文和凭证不进入这份诊断。

| 常见错误码 | 含义 |
| --- | --- |
| `tool_not_advertised` | 调用了本轮目录之外的名称；刷新 MCP 目录，按当前完整名称从新的用户轮次继续 |
| `tool_arguments_schema_invalid` | 模型给出的工具参数未通过本轮公开 Schema |
| `upstream_incomplete_stream` | 上游在完整结束前断开 |
| `upstream_empty_completion` | 上游结束时没有有效正文或工具调用 |
| `upstream_output_limit_reached` | 仅思考后触及模型输出长度限制 |
| `upstream_stream_limit_reached` | 流式传输总量达到配置上限 |
| `upstream_buffer_limit_reached` | 待验证内容的缓冲达到配置上限 |
| `upstream_tool_buffer_limit_reached` | 暂扣工具尾段达到独立预算；该批工具未释放，不可据此声称已执行 |

尚未开始输出时使用对应 HTTP 错误；已经输出安全前缀时，网关使用原生 SSE `error` 结束，并发送 `[DONE]`。失败不生成伪造的模型正文或成功结束标记，不自动重放工具或调高输出额度。网络结果未知、输出超限等失败不能视作可安全自动重试。

有一个严格限定的流式空正文恢复：首次上游为 2xx，完整收到结束标记和唯一 `finish_reason=stop`、只有一个 choice、已输出思考但没有正文/拒绝/音频/工具调用/错误/未知生成字段，且检查均通过时，网关最多再请求一次相同的已编码请求。恢复沿用原路由、轮次、总截止时间和总流量预算，不新建唤醒、不再消费工具结果；客户端断开或轮次已被替代时不继续。它不是断流、长度截断或已发生工具动作后的通用重试。

这次恢复可能额外产生模型费用。普通 `usage` 保持最终尝试口径，`st_gateway_retry` 与安全日志 `gateway_empty_completion_recovery` 分列尝试及总用量；缺失计量仍为未知，不重复相加，也不把总计费输入当单次上下文长度。详见[缓存问题诊断](../docs/CACHE-TROUBLESHOOTING.md)。

人称预览额外字段的提示会说明带 `/` 的合法路径形式，并按当前公开工具契约提供示例；额外键的显示经过安全限制，参数原值留在诊断范围之外。目录或参数错误发生时，该批工具仍未交给客户端执行。重试前先读取已有目标的当前状态，可避免把更早已完成的操作重复执行。

客户端如何长期展示 SSE 错误取决于其实现。有些版本只短暂显示错误卡，历史记录可能只留下已经收到的思考。反馈时保留时间和错误码，有助于区分客户端显示、上游结束方式与工具参数失败。本轮诊断增强提供定位线索，历史“长思考后截断”的每一种原因仍需对应日志核实。

## 启动与边界配置

推荐先按 [GUIDE](../docs/GUIDE.md) 配置独立空白实例，再通过 [OPERATIONS](../docs/OPERATIONS.md) 启动。私有环境已经加载时可运行：

```powershell
python -m rikkahub_gateway.server
```

常用配置示例：

```dotenv
STBRAIN_GATEWAY_CONTEXT_LAYOUT=tail-context-v2
STBRAIN_GATEWAY_MAX_BODY_BYTES=2097152
STBRAIN_GATEWAY_MAX_TOOL_TAIL_BYTES=33554432
STBRAIN_GATEWAY_MAX_STREAM_BYTES=67108864
STBRAIN_GATEWAY_MAX_REQUEST_BODY_BYTES=50331648
```

| 配置 | 默认值与用途 |
| --- | --- |
| `MAX_BODY_BYTES` | 2 MiB：单事件、普通待检查缓冲及非流式响应等通用限制 |
| `MAX_TOOL_TAIL_BYTES` | 32 MiB：从首个工具片段开始暂扣的流式尾段；可配 1 KiB–32 MiB，硬上界 32 MiB |
| `MAX_STREAM_BYTES` | 64 MiB：整段流式传输；可配 1 KiB–64 MiB |
| `MAX_REQUEST_BODY_BYTES` | 48 MiB：客户端请求体；可配 1 KiB–48 MiB |

表中配置均带 `STBRAIN_GATEWAY_` 前缀。工具尾段按 SSE 事件的传输字节计量，包含重复字段与包装，不是文件原始长度或工具参数净长度；小文件的极细分片也会变大。单事件限制、凭证检查和整批验证不因尾段预算变大而放宽。超限不截断参数、不改写事件、不自动重放。

已交付的普通思考和正文无需整轮滞留内存；工具批次仍在完整验证前暂扣。内存峰值另含解析对象和副本，应预留并发余量。以上字节数与模型 token 输出额度是不同设置，并不能解决模型自身输出截断。

健康检查路径为 `/health`；模型目录与生成接口使用网关 Bearer Token。开发模板端口为 `18796`，实际地址以配置为准。

网关、MCP、宿主、人类通道及上游凭证分别配置，运行数据库和秘密放在仓库外。服务默认使用本机监听，由受控 HTTPS 入口向授权设备提供访问。

当前内部 Control 与模型上游 HTTP 客户端均使用 `trust_env=False`，不继承 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或环境 CA 设置；上游也不自动跟随重定向。依赖环境代理或私有 CA 的旧部署需先核对网络与证书兼容性，不能假定原环境变量仍生效。本版未提供一个可替代它们的通用代理环境配置入口；不要以关闭 TLS 验证绕过证书错误。

当前会话与未完成工具链在单实例内维护。更新前结束或明确终止未完成链，完成备份和维护切换后，用新用户轮验收；多实例部署需要另行实现共享会话与工具调用状态。

协议实现与合成测试在本目录；当前发布验证见 [UPDATE-VALIDATION](../docs/UPDATE-VALIDATION.md)。
