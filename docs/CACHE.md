# 缓存与费用

供应商缓存通常重用相同输入前缀，而不是按话题分类。话题变了、但只在原历史末尾新增内容，不必然造成整个历史缓存失效；如果动态召回每轮出现在历史之前并发生变化，则可能较早打断共同前缀。

本开发预览已包含可选择的上下文布局优化，但没有真实缓存命中或费用改善的实测结论。完整保留 AI 原文、来源、披露控制、同轮冻结和跨窗口隔离，不改写哲学层、自我模型或放宽权限。

## 默认与协议

`STBRAIN_GATEWAY_CONTEXT_LAYOUT=legacy` 为默认值。只有宿主通过兼容验证后，才显式设置 `anchored-v1`；不接受其他拼写，也不在验证失败后悄悄降级来掩盖错误。

新布局保留稳定帧在前，将本轮动态帧放在当前人类消息之前。完整上下文包使用 `stbrain-context-layout/1` 契约计算哈希；确认阶段确认完整包，而非沿用旧单条消息哈希。首轮消息数量、内容摘要、当前人类消息位置和真实宿主/窗口/轮次绑定会被保存，同一次生成的工具续轮必须保持它们一致。

## 客户端注意事项

部分 Rikka 客户端会在每次工具续轮重新展开电量、日期、昵称等占位符。例如首轮系统消息中的电量从 60% 变成 59%，即使人类没有改消息，也已是不同输入；新布局会拒绝，而不是假定安全。宿主应在一次 GenerationRun 内冻结已发送历史和占位符展开结果。未经实机确认保留 `legacy`；不能关闭 execution binding 或伪造线程标识绕过拒绝。

同窗口帧变化对比只在宿主实际提供稳定线程头时有效；缺失时记未知，不猜身份。遥测只保留受控模型标识、UTC、用量计数与完整性标记，不保留正文、工具参数、记忆、Key、窗口/轮次标识或内容哈希。

## 数据库迁移

本版为 `brain_context_snapshots` 增加 `context_layout_json TEXT NOT NULL DEFAULT '{}'`。这是加列迁移，部署前须备份并演练旧状态升级、排空未结束工具轮和恢复。切回 `legacy` 只影响布局，不删除新列；不能用旧快照覆盖已有新写入的数据。公开开发启动器不是生产升级管理器。

## 怎样衡量

- 以供应商返回的 input/cache-hit/cache-miss/output 用量为准，缺失值记未知，不写 0 冒充完整数据。
- 区分模型、时间段、价格、输入规模、工具续轮和测试请求；账单截图的总金额不能直接推出命中率。
- 加权命中率为总缓存命中输入除以总输入；不要把每次百分比的平均值当加权结果。
- 小样本中的共同前缀字节增长、单元测试通过，都不等于供应商实际命中改善。
- 默认日志不应记录请求正文、系统身份内容、记忆、工具参数、Key 或稳定个人标识。

真实对比实验应使用明确授权的预算和合成内容，或分析已自然产生且脱敏的用量元数据，不为“预热”持续发送付费请求。
