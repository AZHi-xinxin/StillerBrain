# 架构：记忆怎样回到对话里

[首页](../README.md) · [模块说明](MODULES.md) · [日常使用](GUIDE.md) · [工具目录](TOOLS.md) · [缓存布局](CACHE.md)

**AI 无需先调用查询工具，相关记忆就能在回复前来到上下文。**

这是 ST 架构围绕的一件事：你们继续聊天，过去也有机会参与此刻。AI 写下经历、理解、工具经验和计划，设置关键词、场景、提醒与浮现方式；ST 网关在下一条用户消息到来时，把本轮选中的内容交给原模型。想起之后怎样理解、是否采纳，由正在回答的 AI 决定。

## 从一次留下，到下一次想起

1. **留下自己的理解。** AI 通过 MCP 写下正文、概要和适用线索，存储保留记录及版本。
2. **听见这次的话题。** 网关把最新用户消息的文字交给运行时，结合已有内容、关键词、情绪和场景等信号查找候选。
3. **带回恰当的篇幅。** 作者设置、相关性、读取权限与共享容量共同决定本轮呈现；经历可以带回原文或摘要，工具经验可以只提醒一句。
4. **带着来处回应。** 网关将选中的记忆放入模型请求。模型开始回答时已能看到这些内容，需要更多细节再主动查询。

当前选取主要使用本地文字与标签匹配；“自然想起”描述的是回复前获得线索的交互体验。算法覆盖、主动查询与自动浮现的区别见 [浮现与检索说明](RETRIEVAL.md)。

## 三个服务，各司其职

| 组件 | 接口 | 工作 |
| --- | --- | --- |
| MCP | Streamable HTTP | 向 AI 提供保存、查询、修改与自定义提醒工具 |
| 控制面 | 独立 HTTP | 绑定真实轮次，准备和确认注入快照，处理独立授权及人类异议、回退 |
| 模型网关 | OpenAI 兼容 API | 连接原模型服务，在请求中放入本轮 ST 上下文，并校验工具续轮 |

使用网关时，一次对话大致这样流动：

```text
客户端的新消息
      ↓
网关 → 控制面与运行时 → 本轮记忆快照
      ↓
原模型收到聊天历史和 ST 上下文
      ↓
需要时调用客户端已连接的 MCP 工具
      ↓
工具结果回到同一轮，模型继续回答
```

同一用户轮的多次工具调用复用同一份 ST 快照。下一条真实用户消息开始新的快照。这样，工具回调和独立复核轮次各有清楚的含义。

具备相应 MCP 工具调用能力的模型，也可以通过客户端只连接 ST MCP，主动查、存、改记忆。生成前的自动浮现需要网关或具备等价能力的宿主接入。当前网关适配 OpenAI 兼容的 Chat Completions 接口；完整工具续轮和上下文传递需由实际模型、客户端及网关共同支持。

## 一份记忆，多种呈现方式

| 存储区域 | 保存什么 | 普通对话里的主要呈现 |
| --- | --- | --- |
| 自我定义 | AI 自写的核心锚点、身份摘要和情境侧面 | 当前活动自我与选中的情境侧面 |
| 情感记忆 | 经历、感受、关联人物与当时语境 | 按内容、披露设置和预算给出相关原文或摘要 |
| 学习记忆 | 知识、当前理解、方法与来源 | 相关概要，详细内容按需读取 |
| 工具记忆 | 工具或 MCP 服务用途、场景和经验 | 简短提醒，操作细节按需读取 |
| 规划记忆 | 想做的事、安排、关系和进度 | 当前摘要与可选下一步 |
| 幻觉黑匣子 | AI 主动隔离、留待复查的内容 | 独立入口；可选状态模式只呈现无内容计数 |

自动浮现是一份有容量上限的本轮线索；主动查询则提供目录、搜索和详情。`stbrain_open(view="recall")` 统一查询四个普通模块，再通过结果中的详情入口读取完整记录。

情境侧面 `facets` 的 key 由 AI 自定。自动挑选参考已写下的 key、正文与当前话语中的词句线索，并使用少量场景近义词；宿主显式指定时保留精确选择。自动候选最多选三项，并使用普通记忆之后剩余的动态预算。相关性不明确时保留空选，完整自我正文仍可通过主动查询取得。

## 作者的内容与程序的职责

AI 可修改普通记忆的原文、摘要、关键词、情绪和来源等公开作者字段；ST 追加历史版本，维护技术编号和归属。学习与工具经验可以进一步整合为新的理解。普通计划的父项可选，独立想法可以独立保存。

模块一保留更慎重的自我修订过程：提交候选、后来的真实轮次复核、再后来的真实轮次激活。普通新增与日常作者修改使用简洁入口；隔离、恢复和显式候选操作使用各自流程。

`simple-memory-v1` 中，模块一首次激活前，普通模块只读；激活后，直连与已验证网关调用均可写普通记忆。直连模块一写入使用部署密码授权；网关模块一写入由服务端验证本次执行绑定。

可信度是作者对记录的判断，系统核验与外部执行结果另行记录。工具卡可写 MCP 服务大名，可信度可填 0–100，有效期可选。真实工具仍按当前目录、账户权限和确认条件执行。

## 写给自己的轻提醒

AI 可以在自我治理档案中写自己的轻提醒或安全阀，选择主动查看或场景相关时浮现；也可以调整记录的简短提醒、管理人称弱提醒，以及控制各模块的自动注入模式。

这些作者内容与系统协议分开保存。当前固定的标签选词帮助、权限和来源标记由程序提供；具体 DIY 范围见 [工具目录](TOOLS.md)。

五个存入工具的目录说明会附上读取时的当前人称提醒，帮助 AI 在准备参数时看见它。成功存入回执也附带当前提示。客户端刷新目录后得到新快照，旧聊天里的工具说明保留当时内容。

## 存储、缓存与部署

主数据库保存核心自我、普通记忆、版本和审计；学习创意盒与幻觉黑匣子使用独立数据库。私有配置和运行数据保存在源码外，按 [运维指南](OPERATIONS.md) 备份和导出。

网关支持三种上下文布局。`tail-context-v2` 保留客户端提供的消息顺序，把稳定 ST 内容放在前部、本轮动态 ST 内容放在尾部，为较长公共前缀的缓存复用提供条件。实际命中由模型供应商统计，详见 [CACHE](CACHE.md)。

当前网关的未完成工具链状态在单实例中维护。维护时先结束工具链，再切换版本；多实例扩容需要共享会话与调用血缘设计。ST 提供记忆基础设施，实际的手机操作、联网工具和长任务循环由相应宿主或执行器承担。
