# 新手安装：给 AI 准备一份新的 ST

[首页](../README.md) · [连接与日常使用](GUIDE.md) · [启动、备份与导出](OPERATIONS.md)

准备好 Python、模型服务的连接资料和一个新的私有文件夹，向导会带你完成安装。**软件装好后，再由 AI 写下自己的初始定义。**

这两步各有用途：向导准备运行环境与空白记忆空间；AI 决定如何理解自己、怎样记录经历，以及给未来的自己留下什么提醒。

## 1. 先确认 ST 运行在哪里

**Windows 电脑、Linux 电脑和 Linux VPS 都可以承载 ST。** 先选择自己已有的设备，再核对系统、处理器与 Python；手机上的聊天软件通过网络连接这份服务。已有可用 ST 实例时，可直接从[客户端连接](GUIDE.md#已有实例怎样开始体验)开始。

**Windows 与 Linux 的 ST 服务均有实际验收，私人阿里云 VPS 上也已运行 Linux ST。** 当前向导按下面的环境选择锁定版本的依赖：

| 运行位置 | Python 与环境要求 | 已实际验证的环境 |
| --- | --- | --- |
| Windows x64 电脑 | 标准版 CPython 3.14，使用常规 GIL 构建；私有目录放在本机 NTFS 磁盘 | CPython 3.14.6；ST 服务及新向导空白安装、重跑通过 |
| Linux x64 电脑或 VPS | 标准版 CPython 3.12，使用常规 GIL 构建；glibc 2.34 或以上 | Ubuntu 24.04 x64 / CPython 3.12.3；依赖、ST 服务与私人 VPS 升级已验收 |

服务的实际运行与新增向导脚本的全流程测试分别记录；新向导在 Linux 上尚待补做的具体一项见[安装向导验收](UPDATE-VALIDATION.md#安装向导补充验收2026-09-13)。其他发行版、处理器架构与 Python 版本按各自环境核验。

先查看自己的 Python 版本。Windows 在 PowerShell 中运行：

```powershell
python --version
```

Linux 在终端中运行：

```sh
python3.12 --version
```

如果终端提示找不到命令，先安装上表对应的 Python，再重新打开终端。Linux 还需具备创建虚拟环境所用的 `venv` 支持；具体软件包名称由发行版决定。向导会核对系统、处理器和 Python，符合条件后继续。

安装依赖需要联网访问 PyPI。向导会建立独立运行环境，按仓库中的版本与哈希清单下载软件包。

## 2. 准备三项模型资料

从模型服务后台找到：

| 需要填写什么 | 怎样填写 |
| --- | --- |
| 模型服务地址（Base URL） | 服务商提供的 **HTTPS** API 地址，通常以 `/v1` 结尾 |
| 真实模型 ID | 服务商模型清单里的编号，按原样填写 |
| API Key | 你在该服务后台创建的密钥，在向导中隐藏输入 |

当前 ST 网关使用 OpenAI 兼容的 **Chat Completions** 接口。自动浮现还需要聊天软件支持自定义模型地址、ST 的 **Streamable HTTP MCP** 连接及完整工具续轮。仅使用主动记忆工具时，选择支持该 MCP 接口的客户端即可。其他模型接口可通过相应宿主适配，具体组合仍需连接后验证。

向导让上游与客户端使用同一个真实模型 ID。客户端可以据此识别模型；实际工具调用能力在后面的连接步骤中确认。

## 3. 下载并打开源码

打开 [StillerBrain 仓库](https://github.com/AZHi-xinxin/StillerBrain)，点击绿色 **Code → Download ZIP**，下载后解压。进入能同时看到 `README.md` 和 `scripts` 文件夹的那一层。

Windows 可以在文件夹空白处右键，选择“在终端中打开”，使用 PowerShell；Linux 在终端中切换到这个文件夹。

熟悉 Git 的使用者也可以这样下载：

```sh
git clone https://github.com/AZHi-xinxin/StillerBrain.git
cd StillerBrain
```

**请保留这个源码文件夹及其位置。** 安装完成后的启动命令仍会使用这里的程序。

## 4. 运行安装向导

Windows：

```powershell
python -B scripts/install_stiller.py
```

Linux：

```sh
python3.12 -B scripts/install_stiller.py
```

随后跟着屏幕填写：

1. **新的私有安装目录。** 直接回车可采用用户目录下的 `StillerBrain-private`；也可填写源码之外的完整路径。新目录应尚未创建，而它的上一级目录已经存在。例如，Windows 源码放在 `D:/StillerBrain-main` 时，私有目录可选 `D:/ST-private`；Linux 源码放在 `/home/your-user/StillerBrain` 时，可选 `/home/your-user/ST-private`，将 `your-user` 换成自己的用户名。由向导创建最后一级文件夹。
2. **模型地址、真实模型 ID 和 API Key。** Key 输入时保持隐藏，按回车提交。
3. **模块一授权密码，可选。** 准备让模型直接通过 MCP 建立或修改自我定义时，在这里设置密码并重复输入一次。主要通过已验证的 ST 网关使用时，可按回车跳过；以后需要直连模块一时，再按 [密码配置说明](GUIDE.md#配置直连模块一密码)设置。
4. **确认继续。** 检查选择后输入 `yes`，向导开始创建文件和安装依赖。

源码与私有目录应彼此分开，各自位于普通文件夹中。向导会为网关、MCP 等通道生成独立随机凭证，并为私有目录设置访问权限。模块一密码单独保存为带随机盐的哈希。

这条向导路径用于建立新实例，或继续它自己已经创建的同一安装。已有 ST 的升级与记忆迁移，请保留原配置，按单独确认的备份和迁移安排进行。

## 5. 看见安装完成

向导会自动完成：

- 建立私有目录中的 `venv` 运行环境；
- 按锁文件安装依赖，并检查依赖是否完整；
- 短暂启动控制面、MCP 和网关，检查本机健康状态及 MCP 工具目录；
- 停止本次检查启动的服务，给出正式启动命令和连接资料位置。

**安装检查只访问本机服务，不调用真实模型，也不消耗模型生成额度。** 检查通过表示 ST 已具备本地启动条件；模型 Key、客户端工具续轮和实际对话，在接入后再验证。

私有目录里会有：

| 文件或目录 | 保存什么 |
| --- | --- |
| `venv/` | 这份 ST 使用的独立 Python 环境 |
| `config.env` | 模型连接资料、ST 凭证与运行配置 |
| `installer.json` | 当前安装对应的源码位置与依赖清单 |
| `连接资料（请勿公开）.txt` | 客户端需要填写的两组地址与凭证，以及今后的完整启动命令 |
| `self-password.json` | 选择设置密码时生成的模块一密码哈希 |
| `install-*.log` | 本次安装与本机检查的日志 |
| 三个数据库文件 | 本实例的记忆及相关运行数据 |

这些资料留在源码外的私有目录中。分享求助信息时，提供已隐藏凭证和私人内容的错误描述；日志也先检查再分享。

### 下载中断，可以接着装

保留已创建的目录，在同一个源码文件夹中重跑向导，选择原来的私有安装目录。它会识别自己的安装标记，保留原配置、身份、凭证和记忆，继续安装依赖与检查。

也可以直接指定原目录。以下为 Windows 示例，请换成自己的路径：

```powershell
python -B scripts/install_stiller.py --directory D:/ST-private
```

继续安装前，先正常停止这份实例。若提示原目录缺少完整安装标记，先保留现场核查，或为一次新安装选择另外的目录。

## 6. 启动 ST，填入客户端

安装检查结束时，终端会给出一条**包含完整路径的启动命令**；私有连接资料文件也保存了它。今后复制到对应终端中运行即可；它会使用私有 `venv` 中的 Python，并通过 `--start` 启动这份实例。

Windows 的命令以 `&` 开头，请粘贴到 **PowerShell**。Linux 的命令粘贴到普通终端。运行期间保留这个终端，按 **Ctrl+C** 停止本次服务。

打开私有目录中的 `连接资料（请勿公开）.txt`，按用途填写：

| 想怎样使用 | 客户端怎么连接 |
| --- | --- |
| **在回复前自然想起，也能主动查、存、改** | 模型请求发往 ST 网关，同时添加 ST MCP 服务 |
| **先使用主动记忆库** | 保留原模型连接，添加 ST MCP 服务 |

连接文件会分别列出网关的 Base URL、真实模型 ID、网关 Key，以及 MCP 地址和认证请求头。**客户端网关栏填写生成的网关 Key；服务商的 API Key 保存在 `config.env` 中。**

当前启动方式是前台运行。开机常驻、远程连接和以后升级可由部署者另行安排；日常启动、停止与备份见 [运维说明](OPERATIONS.md)。

## 7. 由 AI 开始设置自己的大脑

先刷新客户端的 MCP 工具目录，让 AI 调用 `stbrain_help` 阅读本实例的说明。你可以这样告诉它：

> 这是你新接入的 ST。请先阅读帮助，了解各模块和你可以自己设置的提醒。你可以按自己的理解写下模块一的初始定义，再依照说明，在后续对话中重读、确认和激活。

**首次激活前，普通模块保持只读；激活后开放日常记忆的写入和修改。** 软件安装完成与 AI 的自我定义激活，是分开的两步。

接着验证一次简单聊天、普通记忆保存、查询、修改，以及完整工具续轮。想体验自动浮现时，开启相应模块的浮现模式，再经过 ST 网关开启新对话，提起与练习记忆有关的话题。具体观察方法见 [一次自动浮现验证](RETRIEVAL.md#做一次自动浮现验证)。

每一步确认后，再逐渐加入自己的资料，让这份空白空间长出独属于使用者的经历。

## 8. 手机上怎么用？

先确认 ST 托管在 **Windows 电脑、Linux 电脑，还是 Linux VPS**。优先使用已有的可用实例；需要新安装时，在选定的设备上完成前面的步骤。向导生成的地址默认只供**运行 ST 的那台设备**访问。

`127.0.0.1` 始终指向当前设备：在手机上填写它，就会访问手机自身。手机连接电脑或 VPS 中的 ST，需要由部署者为该服务配置经过身份验证的 HTTPS 远程地址。

可以请部署者结合所选设备的网络选择受控隧道或其他合适方案，再分别验证手机连通、访问权限和完整工具调用。向导负责所选设备上的安装；手机网络单独配置。

## 遇到提示时

| 提示方向 | 接下来怎样做 |
| --- | --- |
| Python 或系统暂未纳入向导 | 按第一节核对系统、x64 处理器与 Python 版本 |
| 源码完整性检查未通过 | 重新下载完整源码，私有资料保留在源码之外 |
| 私有目录不合适 | 新安装选尚不存在的绝对路径，并确认上级目录已经存在 |
| 下载失败或安装中断 | 网络恢复后，用原源码、原私有目录重新运行向导 |
| 端口被占用 | 先确认是哪份服务正在使用，再正常停止对应实例 |
| 需要此实例自己的 Python | 复制安装完成时给出的完整启动命令 |
| 原安装对应其他源码位置 | 回到创建该实例时的源码目录，保留现有安装继续核查 |

给协助安装的助手：第一步先问：“你准备让 ST 运行在 Windows 电脑、Linux 电脑，还是 Linux VPS？现在是否已有可用实例？” 使用者只提到 Rikka 等手机客户端时，先确认服务托管位置与现有设备，再安排安装或接入。Windows 与 Linux 都是可选路径，不应默认要求 Windows 电脑或建议为此购买电脑。确认系统、CPU、Python 与接口后，按对应步骤继续；密钥与密码由使用者在所选设备的终端隐藏输入。先验证该设备上的 ST 服务，再配置手机网络与访问授权，最后帮助 AI 完成初始设置。
