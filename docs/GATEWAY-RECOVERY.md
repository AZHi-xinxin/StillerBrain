# 网关中断与恢复：给接入宿主的说明

对应 `0.2.0-preview.4`。恢复接口属于已认证宿主的控制面，不是模型工具；不发起模型请求、不重发聊天、不重做工具，也不授予新的记忆写入权限。

## 精确请求控制

宿主为聊天提供稳定的 `X-ST-Thread-ID`，为模型请求提供随机的 32 位小写十六进制 `X-ST-Request-ID`，并保留响应确认的协议和标识。不能从旧消息、界面顺序或当前选择的模型猜测原请求归属。

| 接口 | JSON 字段 | 含义 |
| --- | --- | --- |
| `POST /v1/turns/status` | `model, request_id` | 读取精确请求状态 |
| `POST /v1/turns/stop` | 上述字段及 `binding` | 显式处理已交付工具等待 |
| `POST /v1/turns/finish` | 上述字段及 `terminal_reason` | 宿主在本地生成与工具工作线程终止后报告收尾 |

所有接口继续使用网关认证及精确会话头。`binding` 包含 `session_id`、`generation`、`revision`、`batch_id`；执行时重新比较，过期绑定不能停止新一轮。`terminal_reason` 仅为 `failed`、`cancelled` 或 `budget_exhausted`。终止回执不表示工具成功或副作用撤销，不能在本地工具仍可能执行时抢先提交。

停止和终止针对已交付的工具等待，不能强停仍在生成的模型请求。生成中的请求先取消属于自己的 HTTP 流，再由原处理程序收尾。未知或失败不能直接当作已释放。

## 重启后没有原请求编号

`POST /v1/turns/thread-status` 使用原认证、精确 `X-ST-Thread-ID` 及 `{model, challenge}`。`challenge` 为本次随机的 32 位小写十六进制值，只用于关联响应，不是替代旧请求的编号。该接口拒绝混入 `X-Session-ID` 或 `X-ST-Request-ID`。

- `gateway_lane_idle`：此次读取时通道空闲，不是预约或工具结果证明。
- `owned_busy`：属于当前模型和会话，返回原请求编号及绑定；停止仍受原控制条件限制。
- `busy`：不能确认为该会话拥有，不返回别的会话或请求详情。

查询不创建或停止工作。有限等待只给已断开的原 HTTP 请求收尾机会。遇到忙、超时、缺少协议或归属变化，不可自行清除保护。接口始终不能证明外部工具是否成功，未知结果不会变成成功。

## 断线观察与兼容范围

流式请求收到上游响应头后，独立观察器可唤醒被上游正文读取阻塞的原处理程序。观察器绑定请求代次，结束后解除绑定，不能触及连接池中已交给下一请求的连接。

请求写端 EOF 可能是合法半关闭，因此不能单凭 EOF 结束生成；无正文的 SSE 注释回送失败或连接重置确认接收端不可用后，才中断该请求自己的读取。健康慢流和正常半关闭不据此判为断线。

响应头之前、非流式路径仍使用原超时/收尾机制，不保证同样的及时释放。已交付工具等待继续核对执行状态，不重做工具；旧版默认工具等待仍是未适配客户端的保护，不因新增接口全部取消。

本版无数据库迁移和新默认凭证，原认证与执行保护不变。控制面不记录聊天正文、请求凭证或工具参数。实例升级仍须停止写入者、备份和核对；恢复界面由各客户端独立实现。
