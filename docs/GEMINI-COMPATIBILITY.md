# Gemini 官方接口接入

0.2.8 同步了维护者现用网关的 Gemini 兼容处理；本页介绍的功能已包含在 v0.2.8 正式源码包中。

## 路由范围

图片、系统消息和工具流适配只对服务端配置的 `chat_completions` 路由启用，地址必须为 `https://generativelanguage.googleapis.com/v1beta/openai`（允许显式 443 端口和末尾斜线）。第三方地址及其他协议沿用原流程。

沿用 [多模型路由配置](../rikkahub_gateway/README.md)，为所需模型配置公开别名、上游模型名和独立的密钥环境变量。程序不会自动添加模型、购买额度或修改已有路由。不要把真实密钥放进 Git 或公开配置示例。

如需专用网络出口，可在服务端路由中设置可选 `proxy_url`，形如 `http://127.0.0.1:18912`，指向管理员已运行的本机 HTTP 代理；实际端口由部署者选择。该选项沿用已有回环地址校验，现同时支持 Chat Completions 和 Responses。它不会安装代理，不使用客户端传来的代理地址，也不会更改全局网络设置。

## 上游请求与工具返回

- 多段 SYSTEM 内容在发往 Google 的请求副本中合并，保留完整文本及原位置、名称标签，避免较早的上下文被替换。不支持的内容类型仍报错。
- 历史 assistant、tool、system、developer 消息中的图片保留原图，并在上游请求中放入标有来源的图片资料消息。原文本、完整并行工具结果批次和不透明工具签名保留。
- 原始聊天、ST 人类输入绑定和记忆采集先按原消息完成，随后才做上游副本适配。图片资料消息不回写聊天或作为新人类输入采集。
- Google 流式事件若提供完整函数名、调用 ID 和 JSON 对象参数却省略调用索引，适配器会补齐索引。缺失内容、混用两种索引形式或重复调用 ID 仍报错；已有索引的正常增量保持原样。

## 思考摘要

本次摘要参数转换限定为 Google 官方 HTTPS、标准端口、`chat_completions` 协议的 `gemini-4-argon` 上游模型。它会通过 `extra_body.google.thinking_config.include_thoughts` 请求摘要，保留显式的 `false`；`reasoning_effort` 的 `minimal` 映射为 `low`，`low`、`medium`、`high` 映射为对应原生等级。没有指定等级时不强行设置等级。

未知值、无效结构或与显式原生等级／预算冲突的参数保留给上游校验，不静默猜测。其他模型不因名称相似而启用这段转换。摘要是否返回及其内容由上游决定；网关不生成、补写或解析工具签名。

## 验证范围

维护者的已部署实例完成过官方接口的合成图片、系统消息、工具往返与摘要验证，摘要显示也有配套客户端使用反馈。公开源码另跑隔离回归，详情见 [验证记录](UPDATE-VALIDATION.md)。这些证据不代表所有模型、客户端、账户或网络都已通过，也不承诺每次请求都会返回摘要或达到特定缓存命中率。

本次没有数据库结构变化。公开版既有 Claude 显式路由缓存兼容、DeepSeek 和 Responses 行为继续保留；真实路由配置、聊天、记忆和凭据不随源码分发。
